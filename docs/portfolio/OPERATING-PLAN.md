## 2. Profile homepage blueprint

1. **Hero:** Paul Chumbow / Chumbow Lab, one clear identity statement and a concise positioning line.
2. **Proof:** links to inspectable projects, not unsupported performance statistics.
3. **What I do:** web and WordPress, digital operations, business tools, AI-assisted workflows.

A GitHub profile README is displayed only when a public repository named exactly chumbowlab/chumbowlab exists and contains a README.md at its root. The profile copy in PROFILE-README.md is prepared for that repository.

## 4. Quality gate

Before publishing a profile or repository update, check:

- Every factual claim has a link, artifact or reliable first-hand basis.
- The project status is explicit: prototype, in development, beta or production.
- Screenshots show the real interface and have useful alt text.
- The README explains the problem, approach, stack, capabilities, limitations, setup and next step.
- No secrets, private customer information, personal tenant details or unauthorised client assets are present.
- Dependencies and external services are described accurately.
- The primary CTA works and points to a monitored contact route.
- No performance, security or business-impact metric is published without measurement evidence.

## 6. Search and AI-answer readiness

Use descriptive repository names, accurate one-sentence descriptions, question-led headings where natural, and self-contained opening paragraphs. Include named technologies and explicit limitations. These practices improve clarity and machine readability; they do not guarantee search rankings, indexing or AI citations.

## 7. Thirty-day measurement plan

**Day 0 baseline:** record GitHub repository views, unique visitors, clones, referrers, stars and forks from the repository Traffic tab. Record portfolio visits and enquiries separately if analytics are available. These baseline figures have not yet been captured.

**Week 1:** publish the verified project README and profile README when the profile repository is available. Record the first seven-day traffic baseline.

**Week 2:** add one real product screenshot and test the local setup instructions with a clean browser session.

**Week 3:** publish one additional repository only if its working artefact and documentation pass the quality gate. Share one natural LinkedIn post linking to the relevant project.

**Week 4:** compare views, unique visitors, clones, referrers, stars, portfolio visits and qualified enquiries against the baseline. Note which project or source brought visitors.

**AI-answer spot checks:** ask ChatGPT, Perplexity and Google search/AI experiences questions such as “Who builds practical WordPress and digital operations solutions in Kenya?” and “What is Chumbow Lab Property Operations?” Log the date, exact query, result and whether a source link appears. Treat this as observation, not a promised ranking.

## 8. Current implementation boundary

The connected GitHub tools can read repositories and create or update files in an existing repository. They do not currently expose repository creation, profile bio editing, repository pinning or topic-setting actions. Accordingly, this repository now contains the profile README draft, but the special profile repository and account-level settings remain activation steps to complete in GitHub's website.

The next implementation step is to create the public repository named chumbowlab, add PROFILE-README.md as its root README.md, then apply the topics above and pin only projects that have passed the quality gate.
